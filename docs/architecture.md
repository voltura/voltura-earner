# Architecture

Voltura Earner is a .NET 10 WPF application with a small Windows Forms notification-icon bridge. Its only external application runtime package is MiniExcel for Excel export. Windows x64 is the packaging target.

## Owners

- `App` owns startup, the single-instance lifetime, application shutdown after the runtime closes, and isolated review entry points.
- `AppRuntime` owns commands, persistence, tray lifetime, the live popup, and update coordination. It disposes these services on exit.
- `TrackingSession` owns accounting independently of any window. Monotonic elapsed time prevents wall-clock corrections from inflating or losing time. Rates and currencies belong to individual entries; daily costs and targets belong to a day.
- `MainWindow` and `LiveEarningsView` render state and raise actions. The main dashboard and tray popup use the same view and the same session. The popup has no accounting timer of its own.
- `JsonStore<T>` validates and writes snapshots on a worker thread, using a temporary file and atomic replacement. Invalid existing files remain intact.
- `AppRuntime` holds an exclusive `.earner-work.lock` file beside the active history, preventing separate copies from overwriting the same history. Folder changes acquire the destination before copying and retain the old lock until the new settings are saved. The empty lock file remains after exit; its open handle determines ownership.
- `ReportService` selects real calendar ranges and writes Excel reports off the dispatcher. Currency totals remain separate. Cancellation leaves an existing destination unchanged. Automatic reports use numbered filenames when a report already exists; only an explicit Save dialog can authorize replacement. AppRuntime owns one export at a time, including automatic reports. Canceling an automatic export aborts the enclosing reset or exit. Failure to open a saved workbook does not undo a successful export or prevent exit.
- `UpdateService` and `UpdateVerifier` use WeekNumber's restricted HTTPS downloads, RSA-PSS manifest verification, SHA-256 checks, and explicit install action. The embedded public key belongs to Earner.

## Tracking behavior

Startup loads settings and applies the selected theme before showing the main window. Autostart-to-tray never shows and then hides the window. Start explicitly begins work. Pause, task changes, and edits settle the current entry before changing state. A new application process starts paused. If loading fails, both Exit and the title-bar X close the application without overwriting data. After successful startup, the main window's X hides it while tracking continues in the tray; the first use explains this with a notification. Tray Exit performs the confirmed, saved shutdown. Sleep pauses tracking. The first valid instant of the next local day closes the previous day and pauses, including skipped or repeated midnight; time spent waiting to begin the new day is not counted.

The daily hours setting is a regular-time target. Overtime can be disabled, paid at the regular rate, or paid at a separate hourly rate. The split Start button's menu can start overtime immediately or start regular time with the automatic transition at the daily limit. Explicit overtime remains active when switching tasks, but is unavailable when overtime is disabled. The ordinary Start button always starts with automatic classification. This choice is session state; recorded time and pay remain in the existing work entries. All worked time still counts toward the daily limit. When overtime is disabled, tracking stops exactly at the target and saves the final entry. Each entry retains both rates; changing preferences never recalculates past pay. Fixed daily cost is deducted once per day. Changing rate or currency affects subsequent tracking; historical entries keep their values. Updating today's cost and target is an explicit preference; it does not rewrite previously classified time.

Work-history writes are serialized. While tracking, the visible dashboard refreshes once per second. Hidden windows have no display refresh timer; checkpoints run at most every 30 seconds, with earlier settlement at the target or midnight. Paused tracking has neither a display timer nor a checkpoint timer. Disk access, validation of stored histories, history projection, and report generation run off the UI thread.

Task changes take effect after their settings are saved. Tracking continues during that save and during the following history write, without an uncounted disk-write interval. Pinning and update preferences also preserve running tracking. Saving the Preferences form still explicitly pauses tracking. A checkpoint that crosses a stopping boundary writes the final settled interval before finishing.

Live settings changes update their controls without repopulating the Preferences form. Failed task-selection saves restore both selectors to the committed task. Explicitly applying today's daily cost updates its currency with the amount, while existing work entries keep their original currency and earnings.

Windows sign-out and shutdown settle and save work through a bounded session-ending operation. The dispatcher stays responsive while disk work runs. If enabled, an automatic report is saved without launching a workbook viewer. An outstanding settings/edit command, a save failure, or a save taking longer than four seconds declines Windows shutdown; the app remains available to finish or retry saving before the user retries shutdown. This preparation does not dispose the runtime on a failed attempt.

The live popup follows WeekNumber's native rounded-window and monitor/DPI placement logic. Drag its header to move it. Pinning retains it above other windows and prevents outside-click dismissal. Reopening places it beside the tray again. The main window's pin is independent.

The popup measures its content before opening, so its normal layout fits without scrolling. It uses a single header row with a status pill; scrolling is reserved for a monitor work area smaller than its content. Tooltips are dismissed on deactivation, hiding, clicks, and key presses, and do not reopen just because a control receives keyboard focus.

Work-log rows summarize one task per day. Individual entries remain available when editing or deleting, preserving their exact times, rates, currencies, and earnings. A fixed footer shares the table's column widths and shows time, overtime, and gross earnings for the selected period. The groups and totals use the same snapshot and are calculated off the dispatcher. Currency totals are never combined into a single amount. The grid uses app colors in both themes, has no row-header gutter, and sizes content columns while sharing remaining width between task and earnings. Hour fields display at most four decimal places and retain the exact stored duration when left unchanged. Excel hour values are rounded for display without modifying history.

The task manager saves its added and removed tasks on Close, Escape, or the title-bar X. Opening the manager keeps tracking active. Use task switches a running timer to the selected task; Close keeps it on the current task. A paused timer stays paused. Adding a task does not change the active task by itself.

On normal startup, WeekNumber's tray visibility helper promotes only Earner's executable in the current user's notification-area settings, refreshing the icon only when needed. Registration retries stop after five seconds; placement is attempted once and later user ordering is preserved. Isolated tests and review captures do not modify the real tray settings. The Preferences tab keeps its save action below the scrolling settings.

The tray context menu uses WeekNumber's renderer and follows the Windows taskbar theme. Confirmation dialogs use its themed window layout and default to Cancel. Currency suggestions are a small offline list covering the installer languages and common currencies, using [ISO 4217 codes](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html). Fresh settings default to USD; existing and custom labels remain unchanged. Selecting a suggestion stores only its code, without converting any amounts.

## Installation and release

NSIS uses WeekNumber's Unicode MUI2 wizard, DPI manifest, LZMA compression, developer and company metadata, translated installer text, and maintenance transaction. Standard packages acquire a missing Microsoft runtime; full packages include it. Maintenance validates payloads, ownership, and paths and journals replacement for rollback and recovery. Maintenance waits briefly for an exiting app and otherwise refuses installation or removal while Earner is running; it never force-kills the app. The in-app update action pauses and saves work, launches setup, then closes through AppRuntime. A failed launch leaves the app open and paused. Cancellation after setup opens requires reopening Earner. PowerShell 5.1 compatibility is required for installed maintenance.

`scripts/release.ps1` prepares, tests, packages, signs, and optionally publishes a release. `-PrepareOnly` produces local artifacts without committing or publishing. Signing credentials live outside the repository. The update manifest signature is independent of Windows Authenticode signing.
